## 为什么先定义演示边界

智慧温室涉及传感器、控制器、网关、规则引擎和现场网络。个人项目不应该用一张漂亮的看板掩盖这些现实边界。我的第一步不是画页面，而是明确当前版本只验证三件事：

1. 使用者能否快速理解环境状态；
2. 自动控制与手动控制能否清楚切换；
3. 没有真实设备时，演示流程能否稳定复现。

## 三种运行类型

为了避免业务组件直接判断数据来自哪里，可以先建立统一的数据接口：

```ts
type RuntimeMode = "simulation" | "external" | "playback";

interface SensorReading {
  deviceId: string;
  value: number;
  recordedAt: string;
}
```

| 类型 | 数据来源 | 适合场景 |
| --- | --- | --- |
| simulation | 本地生成 | 日常开发与答辩 |
| external | 预留网关接口 | 后续设备联调 |
| playback | 历史快照 | 稳定复现特定过程 |

## 报警不是一条红色消息

报警至少需要说明发生了什么、影响哪个设备、当前是否仍然存在，以及使用者可以做什么。视觉上的红色只是状态表达的一部分，不能代替处理流程。

### 当前仍需验证

- 外部设备接入协议；
- 真实网络环境中的延迟；
- 报警规则在不同作物场景下的有效性。

这些内容在完成真实验证前，都不应被描述为已经解决。
